# Working In This Repository

## Start Here

1. Read `docs/domain/trade-lifecycle.md` before changing trade behavior.
2. Read the relevant ADR under `docs/adr/` before changing persistence, transport, or API contracts.
3. Treat `openapi/openapi.json` and `frontend/src/api/generated/` as generated output. Change backend Zod schemas, then run `npm run api:generate`.
4. Use `design_handoff_fusion_trade_blotter/README.md` as the canonical spec and `designs/Fusion Trade Blotter v2.dc.html` as the visual reference. Do not port `designs/support.js`.

## Module Boundaries

### Backend

A modular monolith: organised first by business module, then by technical responsibility inside it. Each module is `routes/ -> schemas/ + dtos/ -> services/ -> repositories/`.

- `routes/` is a thin HTTP layer: validate, build the service input from the request plus the session, call a service. No business rules, no Prisma, and **no error handling** — every failure is thrown and mapped once in `infrastructure/errors/error-handler.ts`, which is what keeps one error envelope across the whole API. An error carries its own context by overriding `ApplicationError.body()`.
- `schemas/` owns Zod request/response shapes and the OpenAPI contract, split per use case.
- `dtos/` is what a service receives. Where that is exactly the validated request, the type is inferred from the schema (`z.infer`) rather than restated; where the server adds something the client may not supply, the DTO is the inferred type plus that field (`… & { actor: TradeActor }`).
- `services/` owns business rules and orchestration, and publishes notifications only after a commit. No Fastify, no Prisma.
- `repositories/` owns Prisma and transactions. Methods are use-case-specific so a caller cannot break atomicity. A mutation returns the row PostgreSQL stored, never the one it was asked to store — the two differ wherever a column is narrower than the value handed to it.
- `services/trade-lifecycle.ts` holds the pure lifecycle rules — a private helper of the service, and the cheapest place to test create/amend/execute/cancel. It decides a `TradeMutation`, which deliberately excludes `createdAt` and `updatedAt`: timestamps belong to the database.
- Audit lives inside the trades module (`repositories/trade-audit.repository.ts`) and its writes take the caller's transaction client, so an audit event can never commit apart from its trade change. Its `after` snapshot is taken from the persisted row, so the log cannot describe a state that was never stored.
- `auth` owns login, logout, session resolution, and the `requireAuth` guard.
- Cross-cutting `realtime/` and `infrastructure/` sit outside the modules.

**Every module has an `index.ts`.** Cross-module imports go through the barrel, never into another module's internals. `trades/services/` must not import `auth` at all — it receives an authenticated actor as a plain value.

Nesting stops at `modules/<module>/<layer>/<file>`.

All of the above is enforced by ESLint. Run `npm run lint:boundaries` — it appends a forbidden import to each real file and asserts lint rejects it, because a `no-restricted-imports` rule fails silently if its patterns or config precedence are wrong.

### Frontend

- `components/ui/` holds vendored ShadCN primitives. They are generated by `npx shadcn@latest add <name>`, not hand-authored — avoid editing them, and re-apply any necessary patch if you regenerate one.
- `components/layout/` holds app chrome shared across features.
- `features/<name>/{components,hooks,lib}` owns one vertical slice. A feature may import from `components/`, `hooks/`, `lib/`, `types/`, and `api/`, but never from another feature's internals.
- `features/*/lib/` holds pure, tested logic (derived metrics, aggregates, diffs). Put calculations there, not in components.
- `api/generated/` is generated. `api/realtime/` is the handwritten SSE adapter. `api/unwrap.ts` narrows generated response unions.
- The frontend consumes generated API types. Do not hand-maintain duplicate DTOs or endpoint wrappers. Form validation runs the *generated* request schema (`api/generated/validation/**`) rather than a hand-written copy, so it enforces exactly what the server does.
- `features/*/hooks/` owns state that spans several components. The blotter's is split by concern: `use-blotter-query-state` (what is being looked at, mirrored into the URL), `use-row-cursor` (keyboard cursor and selection), `use-trade-workflow` (what the user is in the middle of doing, including the form's values), `use-trade-stream` (notifications). Components receive state and callbacks; they do not own workflow.
- Resets belong in event handlers, not effects. `useTradeWorkflow` owns the form's values so that opening a form or accepting a newer version is a user action, and a re-render caused by an incoming SSE event can never disturb what someone has typed.

## Styling

- Tailwind v4 with two token layers in `src/styles.css`: the ShadCN semantic contract (`--primary`, `--background`, …) is **derived from** the blotter tokens (`--surface`, `--ink-*`, `--violet`, `--green`, …), so the two cannot drift.
- Never hardcode a hex value in a component. Add or reuse a token.
- Dark mode is a single `data-fusion-theme` attribute on the root. Every colour must resolve through a token so no component needs light/dark branching.
- Use the design's type scale (`text-cell-2`, `text-body-2`, `text-title`, …), not Tailwind's defaults. If you add a step, register it in `cn()`'s `font-size` group or `tailwind-merge` will treat it as a colour and silently drop colour classes.
- Radii: `rounded-xs` 3px (kbd), `rounded-sm` 4px (tags/chips), `rounded-md`/`rounded-lg` 6px (buttons, inputs, cards, dialogs), `rounded-xl` 8px.
- Icons: Lucide only, 13–16px. Shadows only on popovers, drawers, and dialogs.

## Invariants

- Valid trade status: `NEW | EXECUTED | CANCELLED`.
- `AMENDED` is an audit event, never a trade status.
- `EXECUTED` and `CANCELLED` are terminal.
- Every successful trade command writes exactly one audit event atomically.
- Every non-create command requires `expectedVersion`.
- Never accept `actorUserId` or `trader` from a command payload.
- Notional, signed quantity, and signed notional are derived in `features/trades/lib/trade-view.ts`; they are never persisted, sent in a command, or written to an audit snapshot. *Ordering* by them is the database's job — PostgreSQL sorts on the same expressions, so a derived sort covers every matching trade rather than the loaded page.
- Aggregates come from `GET /api/trades/exposure`, scoped by the same filters as the list. Never sum the current page: a page total presented as a book total silently changes when the user pages.
- Monetary aggregates cross the wire as decimal strings. A sum of `quantity * price` can exceed what a JSON number holds exactly.
- An amendment sends only the fields the user edited. Resubmitting untouched values overwrites whatever a concurrent amendment wrote to them, which is a silent merge.
- SSE is a notification channel, not the source of truth. Refetch REST state on connect and reconnect; never apply an event's payload directly to the cache.
- Connection state is derived in `features/trades/lib/connection.ts` from three signals — `navigator.onLine`, a permanently closed `EventSource`, and elapsed heartbeat silence. Never rely on `EventSource.onerror` alone: a broken socket can stay open for minutes without raising it. Keep the client silence window above two server heartbeat intervals.
- The stream heartbeat must stay a *named* SSE event. `EventSource` never surfaces comment frames (`: ping`) to JavaScript, so a comment keeps proxies awake but leaves the client blind.
- Never overwrite an open form from a remote update — raise the stale banner instead.
- A `409` renders the conflict diff. Never auto-merge. "Reapply" moves the baseline onto the server's version and keeps the user's edits; it does not resend fields they never touched.
- Commands are never gated on the stream. SSE is a notification channel, so a dropped connection means the table may be behind — shown as a banner — not that the desk is closed.
- Execute and cancel require explicit confirmation because they are terminal.
- Monetary values in the table are fixed-precision, never abbreviated. Timestamps render `YYYY-MM-DD HH:MM:SS` in UTC.

## Verification

Run the narrowest relevant command while iterating and `npm run verify` before finishing.

- `npm run verify` — contract drift, types, lint, boundaries, tests, production builds
- `npm run api:check` — regenerates the contract and fails if committed output was stale
- `npm run lint:boundaries` — asserts the architecture rules actually reject violations, backend layers and frontend feature isolation alike. It writes a throwaway probe file beside each real one; it never edits tracked source.
- `npm run test:domain` / `test:integration` / `test:frontend`
- `SEED_RESET=true npm run db:seed -w backend` — rebuild demo data (5,000 trades, mixed lifecycles). `SEED_TRADE_COUNT` overrides the size. The seed is deterministic, so a bug found against seeded data reproduces.

Changes to lifecycle behavior require domain tests. Changes to persistence or route contracts require an integration test. Changes to frontend calculations require a unit test in the owning `features/*/lib/`.
